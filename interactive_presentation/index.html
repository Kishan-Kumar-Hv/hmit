FOUNDATION & THREAT MODEL

Problem Statement & The "Last-Inch" Threat Model

Original Assigned Problem Statement

"Design and engineer a real-time secure communication system that eliminates vulnerabilities in both data transmission and physical message presentation. The application must guarantee that confidential exchanges remain fully protected from over-the-shoulder eavesdropping, unauthorized physical device access, and persistent forensic extraction, while providing zero-knowledge verifiable privacy and high usability."

1. The "Last-Inch" Presentation Vulnerability

Conventional E2EE (Signal, WhatsApp) encrypts data in flight via TLS. However, once decrypted onto the recipient's screen, it exists in plain sight. In public environments—coffee shops, shared offices, airports, and transit—shoulder surfers and bystanders compromise confidentiality completely.

2. Static vs Continuous Active Authentication

Modern apps authenticate biometrics (Face ID, PIN) only ONCE when launching the application. If an unlocked smartphone or laptop is left unattended on a desk or handed to a coworker, any unauthorized person has unrestricted access to private messages.

3. Persistent Forensic Media Residue & Caches

Standard messaging apps write received attachments to local device flash storage, OS media caches, and SQLite databases. Even after 'deleting' messages or enabling disappearing timers, forensic extraction tools routinely recover sensitive image attachments and thumbnail artifacts.

4. Traffic Observability & Lack of Deniability

Transmitting raw encrypted binary blocks openly signals to network firewalls, internet service providers (ISPs), and eavesdroppers that sensitive, confidential communication is taking place. Users completely lack plausible deniability without an innocuous, covert carrier mechanism.

PHASE 2 DEVELOPMENTS

Implementation: 5 Core Engineering Features

01

Zero-Knowledge Biometric Enrollment & Vector Encryption

Mandatory registration captures exactly 1 face using InspireFace. Extracts 512-d normalized floating point embeddings. The Node.js backend encrypts the vector with AES-256-GCM using a server master key. The raw user photo is purged from memory immediately—never stored on disk.

02

Randomized PRNG LSB Steganography Engine

Disguises encrypted secret text into lossless PNG carriers. Writes a 24-byte header (CVS1 magic tag, 16-byte random PRNG seed, 4-byte payload size) into initial pixels, then scatters encrypted bits randomly across RGB channels via NumPy default_rng. Resulting image exhibits zero perceptible visual degradation.

03

Active Face Guardian Surveillance Loop

Decryption activates recipient webcam. The AI verifies identity against enrolled template (cosine >= 0.70) and guarantees exactly 1 face. A continuous surveillance loop checks the viewer every 1.5s with a 2s AbortSignal timeout. If the user turns away or a second face appears, text is auto-concealed.

04

Single-Port Cloud Bundling on Render

Cloud PaaS provides only one public port ($PORT). Team Veltrox engineered a root build script compiling Vite SPA and Express server into a unified artifact. Express 5 acts as reverse proxy, serving React statically from dist/ and handling catch-all SPA routing seamlessly.

05

Forensic Database Self-Healing

Traditional apps leave persistent traces of decrypted media. Chatvia implements atomic self-healing: upon single-view decryption, PostgreSQL updates attachments with the original clean PNG and nullifies original_png, removing any forensic trace of steganography.

ENGINEERING LESSONS

Challenges Faced & Engineering Solutions

1. Render Single-Port Limitation ($PORT)

Solved

Cloud PaaS allows only 1 exposed port, but we required React SPA, Express API, and WebSockets. We built a unified root build pipeline compiling both services, using Express 5 as reverse proxy serving Vite dist/ statically.

2. Supabase SSL Pooler Rejection

Solved

Node.js pg crashed with SELF_SIGNED_CERT_IN_CHAIN on cloud poolers. We implemented dynamic SSL detection in db.ts automatically applying { rejectUnauthorized: false } whenever DATABASE_URL is present.

3. Python 3.12 InspireFace C-Bindings Wheels

Solved

InspireFace lacks prebuilt wheels for Python 3.13, causing segfaults. We isolated Python 3.12 and introduced a thread synchronization lock (_session_lock) around inference calls to guarantee thread safety.

4. WebRTC Camera Lifecycle Leaks

Solved

Switching tabs or closing cards left webcam hardware active. We implemented HTML5 visibilitychange listeners and ended event hooks to terminate all video tracks immediately upon backgrounding.

5. Steganographic Visual Artifacts

Solved

Sequential LSB causes visible banding in gradients. We engineered a randomized PRNG distribution seeded with a 16-byte cryptographic token, scattering bits across RGB channels with zero perceptual change.
